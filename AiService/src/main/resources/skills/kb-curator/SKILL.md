# 共享知识库维护

本技能按教程的“先查重、再整理、最后入库”流程编写，工具参数适配当前Milvus版本。
知识入库后，其他用户也能检索到。普通聊天、查询已有知识和仅要求总结，不代表授权发布共享知识。

## 1. 确认用户要保存的内容

只处理用户明确提供并要求写入共享知识库的信息。
从用户提供的内容提取一个明确的问题或知识主题，以及对应答案。
内容缺少关键事实或含义不清时，先向用户追问，不编造答案，也不把助手猜测写入知识库。

## 2. 调用searchKnowledge检索查重

提炼核心问题或关键词，调用`searchKnowledge(query)`；不要直接把整段聊天历史作为查询。
该工具复用在线回答的混合检索和精排链路。
对返回内容判断是重复、冲突还是无关，不能仅因检索命中就认为重复。
若工具返回检索失败，停止入库并如实告知用户，不能跳过查重。

## 3. 判断如何处理

- 已有内容完整表达了同一事实：说明知识已存在，不重复写入。
- 新旧事实冲突：列出冲突并询问用户，不擅自覆盖，也不把冲突内容直接追加。
- 内容无关或新内容补充了已有知识：整理为能够独立理解的条目后继续。
- 用户要求修改或删除已有知识：当前工具只支持新增，明确说明能力范围，不声称已完成更新或删除。

## 4. 整理并写入

将`title`设为简洁的主题或问题，将`text`设为完整、清晰且独立可理解的正文。
保存问答时可以使用以下结构：

```text
Q：项目组何时进行值班交接？
A：项目组每周三下午四点进行值班交接。
```

调用`addSharedKnowledge(title, text)`，只写入用户要求发布的内容。
当前项目由该工具执行文档切分、Embedding并写入Milvus；没有本地Markdown文件名参数。

## 5. 根据真实结果回复

只有入库工具成功返回docId，才告知用户已保存，并可附上该docId。
工具失败时如实说明，不声称已保存，不盲目重复调用写入工具。
