# 聊天记录接口测试（50 条本地种子消息）

本文对应当前 `MessageController`、`MessageServiceImpl.search`、`MessageIndexConsumer` 和 **2026-11-02** 实际写入的测试消息。参照联系人接口测试文档，给出请求路径、Header、Body、记录数量、排序和实际验证结果。

本次向 MySQL `infinitechat.message` **新增 50 条文本消息**：主会话 40 条、对照会话 10 条。没有手工向 ES 插入文档，50 条数据通过现有 **MySQL → Canal → Kafka → ES** 链路同步。ES `message` 索引核对为 50 条，索引消费组 `CURRENT-OFFSET=50 / LOG-END-OFFSET=50 / LAG=0`。

本次使用当前代码打包后启动临时验证实例，完成验证后停止该实例，保留数据库、Redis 和 ES 数据。自行测试时，先启动本项目 MySQL、Redis、Kafka、Canal、ES 和 **OfflineDataService**；IDE 默认启用 Nacos 注册时也需要 Nacos。以下请求均直连 `http://localhost:8101`。

## Header 与鉴权

| 访问方式 | Header | 当前行为 |
|---|---|---|
| 直连 OfflineDataService `:8101` | `Content-Type: application/json` | 当前搜索接口没有读取用户身份、没有检查会话成员，下面请求不需要 Token。 |
| 经过 Gateway `:10010` | `Access-Token: <登录返回的 accessToken>`，另加 JSON Content-Type | 已有 `/api/message/**` 路由；网关仍验证 Access-Token。Refresh-Token 可带，但不是正常访问必传。本次未测试 Gateway。 |

Header 名称是 `Access-Token`，不是 `Authorization: Bearer ...`。这里的会话隔离测试只证明 ES 按 `sessionId` 过滤正确，**不代表已实现会话访问权限校验**。

所有正常响应的 HTTP 状态为 `200`，统一外层是 `{"code":200,"data":...,"message":"ok"}`。下文没有省略任何请求字段；响应使用数量和 ID 范围描述长列表，并在需要处展示真实记录或完整空结果。

## 搜索接口参数

```http
POST http://localhost:8101/api/message/search
Content-Type: application/json
```

Query 参数：无。Path 参数：无。Body：

| 字段 | 是否必填 | 说明 |
|---|---|---|
| sessionId | 是 | 当前仅支持单会话搜索，使用项目现有字段名 |
| keyword | 是 | 1～100字，去首尾空白后通过 IK 分词；分词之间为 AND |
| pageSize | 否 | 默认20，大于100按100处理；小于等于0拒绝 |
| startTime | 否 | 包含起点，支持 `Z`、`+08:00` |
| endTime | 否 | 不包含终点；与起点同时存在时必须晚于起点 |
| cursor | 否 | 第一页为空，后续传上一页的 nextCursor |
| cursor.createdTime | 有cursor时必填 | 上页最后一条的毫秒时间戳 |
| cursor.messageId | 有cursor时必填 | 上页最后一条的消息 ID |

没有 `pageNo/pageNum`、`senderId`、`sortMode`、跨会话搜索或消息类型切换。当前统一搜索文本，按时间倒序。变更关键词、会话或时间范围时清空 cursor。响应 `createdTime` 使用项目 `FormatDateUtil` 输出北京时间字符串 `yyyy-MM-dd HH:mm:ss`；游标内仍是毫秒时间戳。

## 10. 非法请求：参数校验与统一异常返回

首次端到端验证时，以下3类请求均返回 HTTP 500。2026-11-02 后续已添加 Request 的 `@NotBlank`、Controller 的 `@Valid`、可选 cursor 的嵌套校验和校验实现，并在 OfflineDataService 导入 Common 的 `GlobalExceptionHandler`。重启使用新代码的服务后，按现有 Common 约定返回 **HTTP 200 + JSON 业务错误码**：注解校验失败为 `50003`，Service 的 `PARAMS_ERROR` 为 `40000`。这里的 `50003` 是业务码，不是 HTTP 500。

补充验证使用不连接外部基础设施的 MVC 测试：首请求 null 游标、完整游标、缺失游标消息 ID、空白会话和关键词，4项均通过。尚未重新执行此前完整的50条消息端到端测试。

### 10.1 缺少会话 ID

### 10.2 起点晚于终点

```json

  "keyword": "IMES50",
  "pageSize": 20,
```

当前预期：Service 抛出业务异常，由公共异常处理器包装为 HTTP 200、业务 `code=40000`、`message=起始时间必须早于结束时间`。时间先后关系继续由 Service 检查。

### 10.3 cursor 缺少 messageId

```json
{
  "sessionId": "930000000000001001",
  "keyword": "IMES50",
  "pageSize": 20,
  "cursor": {
    "createdTime": 1793499660000
  }
}
```

当前预期：嵌套参数校验拦截，不调用搜索 Service。HTTP 200、业务 `code=50003`，例如：

```json

```

## 排查方式

- 连接不到8101：先启动 OfflineDataService。本次临时验证实例已经停止，不会替你长期占用端口。
- MySQL 有消息但搜索为空：检查 Canal 是否连接、Kafka 是否有 message-index-topic、消费者是否消费成功，并等待 ES refresh。
- 查询数量不同：使用 keyword=IMES50；查询主会话应共40条，对照会话应10条。用“部署”时，主会话是26条，不是25条，因为第40条也含“部署”。
- 总是在第一页：后续请求没有原样传回 nextCursor。
- 时间差8小时：确认 `Z` 与 `+08:00` 的区别；不要把北京时间直接补一个 Z。
- 索引 health=yellow：当前单节点默认有一个未分配副本，主分片可正常读写，不代表本次50条索引失败。
- 本次仅验证了正常运行下的同步。现有 Canal 的异步 Kafka 发布和自动提交配置仍有已讨论过的失败窗口，不能由这次成功测试推出“消息绝不丢失”。
